# Byte-exact diagnostic output retention

`parallel-shard-runner-process-diagnostic.js --retain-output` adds `runs[].outputs` to the diagnostic JSON. Each entry identifies the command by index/label/state and contains `stdoutBase64` / `stderrBase64`. Decode with `Buffer.from(value, 'base64')`; verify against the corresponding result's byte count and SHA256. No UTF-8 decoding or normalization is applied. Empty captures are empty strings; commands not started explicitly say `unavailable: not-started`. Missing buffers or mismatched counts/hashes fail the diagnostic. Existing exit/signal/timeout/residue/count/output-parity gates are unchanged.

The option is off by default. Production runner, canonical JSON serialization, shard settings and existing diagnostic branch conditions are unchanged. Successful runner buffers are non-enumerable, so the former JSON retained only their hashes/counts. A future justified hosted K observation can add this flag to the existing pinned-source full-shard invocation and upload the JSON using its existing artifact path. This PR does not rerun the completed K experiment or claim new hosted K safety evidence. Retention increases report size (base64 ~4/3 of captured bytes) and diagnostic memory; account for it when interpreting measurements. Runner capture remains bounded by its existing per-command output cap; overflow is still failure, and retained bytes in a failing report may be partial.

`--self-test` executes tiny real runner controls, including invalid UTF-8/NUL bytes and stderr, JSON round trip, unchanged original results, empty failed-command streams, missing captures and corrupt length/hash rejection. The existing mandatory shard-contract job runs this short check. The self-test establishes output retention, **not process safety**. Normal/full diagnostic execution still refuses PID/procfs mismatch before launching test groups; local namespace mismatch remains unqualified.
