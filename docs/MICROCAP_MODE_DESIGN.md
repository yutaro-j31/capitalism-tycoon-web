「たまに黒字だが時価総額が低い企業が上場してきて、フルベットすると数年で

## 1. コンセプト

**Coffee Inc 2で最も楽しかった体験を、既存の株式市場インフラに接続する。**
新しいシステムを作るのではなく、既に存在する `g.market` / `buyStock()` /
`sellStock()` を使う。

新規に作るのは、この市場へ**独立した小型株を定期的に投入する供給源**だけ。

### 既存資産との関係

| 既存システム | 役割 | 今回の扱い |
|---|---|---|
| `g.market` / `buyStock()` / `sellStock()` | 株式売買の基盤 | **そのまま使う** |
| `g.startups`（VC投資パイプライン） | プレイヤーが能動的に出資して育てる | **触らない。別の遊び方として独立させる** |
| `listStartup()` | VC投資先の上場処理 | 参考にするが直接は使わない（§3参照） |

## 2. 既存資産の実測（発見）

### 2.1 既存の新規上場株の値動きは「時々数十倍」止まりで「時には数百倍」に届かない

`updateMarket()` の式（`move = trend + (economy-1)*.018 + rand(-vol,vol)`、
新規上場株は `trend=.004 / vol=.12` で全銘柄一律）をそのまま5年間・3000回試行：

| 指標 | 値 |
|---|---|
| 中央値 | 1.47倍 |
| 90%点 | 6.5倍 |
| 99%点 | 19.2倍 |
| **最大（3000回中）** | **59倍** |
| 10倍以上 | 4.07% |
| 100倍以上 | **0%** |

**「時には何百倍」は現状の式では構造的に起きない。** 全銘柄が同じパラメータの
単純なランダムウォークで、銘柄ごとの性格の違いがないため。

### 2.2 既存の `listStartup()` パイプラインは供給源として使えない

VC投資パイプライン（`g.startups`）経由で市場に上場する頻度を実測した。

```
500週（約10年）・5シードでのIPO件数: 0, 0, 1, 2, 0件
```

**想定より遥かに少ない。** 原因を追ったところ:

- Pre-IPO段階に到達した週のうち**66〜100%が、上場条件（評価額10億円超）に
  まだ届いていない**
- テンプレートの年間成長率が5〜10%と低く、新興企業というより横ばいの
  中小企業の成長率
- ステージ進行（プレイヤーが出資しない場合は週8%の確率）も遅く、
  Seed→Pre-IPOまで平均50週以上かかる
- その間にrunway切れで倒産（write-off）することもある（500週で4〜7件）

**このパイプラインはプレイヤーが能動的に出資して育てることを前提に設計されており、
「放っておいても勝手に上場してくる」用途には作られていない。** 成長率や閾値を
いじって無理に頻度を上げると、VC投資というプレイスタイルのバランスが崩れる。

**結論: 既存パイプラインを改造せず、別の独立した供給源を新設する。**

## 3. 設計

### 3.1 供給: 独立した小型株スポーン

`g.startups` を経由せず、`g.market` に直接新規銘柄を `push` する形で実装する。
`buyStock()` / `sellStock()` は `g.market` を見るだけなので、
既存のVC投資システムには一切依存しない。

| 項目 | 値 |
|---|---|
| 出現頻度 | **範囲抽選**。次回発生を8〜18週後の範囲でランダムに決める（平均13週＝四半期） |
| 上場時評価額 | 10〜19億円程度 |
| 発行株式数 | 既存の `listStartup()` に倣い100万株 |

**範囲抽選を採用した理由:** 固定間隔だと「そろそろ来る」と正確に読めてしまい
緊張感が薄れる。かといって毎週確率抽選にすると「いつ来るか全く分からない」
不確実性が強すぎる。8〜18週のカウントダウン方式なら、プレイヤーは
「そろそろかもしれない」という予感を持てるが、正確な週は分からない
——このバランスが好みとして選ばれた。

### 3.2 アーキタイプ（銘柄の性格）

上場のたびに決定論的ハッシュで抽選する。

| アーキタイプ | 出現比率 | trend | vol | 上場時の性質 |
|---|---|---|---|---|
| 駄目株 | 55% | -0.003 | 0.08 | 無収益（PER=0） |
| 堅実 | 28% | 0.0015 | 0.08 | 黒字（PER 14程度） |
| 隠れた優良株 | 12% | 0.006 | 0.13 | 黒字（PER 9程度） |
| 本物の当たり | 5% | 0.011 | 0.18 | 黒字（PER 7程度） |

**唯一の手がかりは「上場時に黒字かどうか」。** 黒字グループ（堅実・隠れた優良株・
本物の当たり）は上場時点でプレイヤーからは区別できない。ここに賭ける瞬間の
緊張感が生まれる。

**手がかりには15%のノイズを入れる**（駄目株が稀に黒字を装う、本物の当たりが
稀に無収益で上場する）。完全な攻略法にしないため。

### 3.3 判断の軸: いつ売るか

保有期間を固定しない。`sellStock()` は既存関数なのでプレイヤーがいつでも
売却できる。**含み益が3倍になった時点で利確するか、10倍を狙って持ち続けるか**
という判断が、この機能の中心的な意思決定になる。

（PEモードのExitタイミング検討と同種の判断だが、PEでは腕の効き幅として弱いと
判定された。こちらは公開市場の値動きが主体で、当たりの見極めより「降りどき」が
主役になりやすい構造のため、あえて残す。）

### 3.4 資金規模の上限

**§5 のバグは修正済み。** 既存の株価インパクト機構（1取引あたり最大3%、
かつ1回の注文が発行済株式数の5%＝`STOCK_ORDER_MAX_SHARE_OF_ISSUED`まで）が、
そのまま資金規模の摩擦として機能する。新しい上限機構を作る必要はない。

発行株式数100万株の新規上場株なら、1回の注文の上限は5万株。数千億〜
数兆円規模の個人資産を持つプレイヤーでも、1銘柄に全額を注ぎ込むには
複数回に分けて買い増す必要があり、**買い増すたびに平均取得単価が
確実に上がっていく**（本来意図した摩擦どおりに機能する）。

## 4. 検証結果

### 4.1 30年プレイ（一般的なプレイ長）

四半期に1回・黒字の手がかりがある銘柄だけにフルベットした場合（300シード）:

| 指標 | 値 |
|---|---|
| 投資機会数 | 約56回 |
| 倍率中央値 | 1.11倍 |
| 90%点 | 5.7倍 |
| 99%点 | 44.9倍 |
| 最大（300シード中） | 1,756倍 |
| 10倍以上の的中率 | 5.6% |
| 50倍以上の的中率 | 0.85% |
| **50倍以上を一度も引かない人** | **64%** |
| **50倍以上を1回以上引く人** | **36%** |

**「毎回ではないが、プレイし続けていればいつか大化けに出会える」という感覚が
数値として成立する。** 全員が必ず経験するわけではないので、引けたときの
特別感が保たれる。

### 4.2 100年プレイ

| 指標 | 値 |
|---|---|
| 投資機会数 | 約186回 |
| 50倍以上を引く回数（平均） | 1.58回 |
| 一度も引かない人 | 19% |
| 3回以上引く人 | 20% |

長くプレイするほど「いつかは来る」という安心感と、それでも運の差が
残るバランスになっている。

### 4.3 手がかりを無視して全部にベットした場合（比較）

| 指標 | 黒字銘柄のみにフルベット | 全銘柄に分散 |
|---|---|---|
| 中央値 | 1.40倍 | 0.57〜0.60倍 |
| 10倍以上 | 6.5% | 3.0% |
| 100倍以上 | 0.44% | 0.20% |

**黒字の手がかりは意味のある差を生む**（中央値・的中率とも約2倍）が、
完璧な攻略法ではない（手がかりを無視しても投資機会自体は残る）。

## 5. 実装前に見つかった前提バグ（修正済み）

### `buyStock()` に数量の上限チェックがなかった

```js
stock.price *= 1 + Math.min(.03, qty/Math.max(1,stock.issuedShares)*.6);
```

**`qty` 自体には上限が無かった。** 発行済株式数の何倍を1回の注文で指定しても、
株価インパクトは常に3%に固定される（`Math.min` の上限に張り付くだけ）。

これにより、**1回の注文でどれだけ大金を注ぎ込んでも、平均取得単価は
ほぼ上場時の価格のまま**になっていた。株価インパクトが「規模に対する自然な
ブレーキ」として機能していなかった。

### なぜ必要だったか（PEモードの教訓と同型）

株価インパクトが機能しない場合、倍率は投資額に関係なく誰でも同じになる。
プレイヤーの個人資産がPEモードで数千億〜数兆円規模まで育った後、
**その全額を1回の注文で「本物の当たり」に注ぎ込めば、一晩で資産が
数百倍になる**。これはPEモード §12 で26タスクかけて潰した「指数爆発」と
同じ構造の問題であり、この機能に限らず**既存の株式市場全体**に影響していた。

### 修正内容（完了）

**PR #645（`fix/stock-order-quantity-cap`、コミット `ce6ec5f`）でpush済み。**
PEモードのブランチとは分離し、`origin/main` から独立したブランチとして
作業された（AGENTS.mdの「1機能1PR」原則に従う）。

- 定数 `STOCK_ORDER_MAX_SHARE_OF_ISSUED = .05` を追加。
  **1回の注文で動かせる数量を発行済株式数の5%までに制限**
- `buyStock()` / `sellStock()` の両方に上限チェックを追加。上限を超える
  注文は**拒否せず自動的に上限まで減らし**、通知メッセージに調整があった
  旨を付記する（エラーで弾くのではなくクランプする設計。既存の大量保有
  プレイヤーの操作性を損なわない）
- 発行済株式数がほぼゼロの銘柄は取引そのものを拒否（ゼロ除算ガード）

**検証**: 新規テスト `tests/stock-order-quantity-cap-test.js`（6シナリオ）で、
発行済100万株の銘柄に1000万株（10倍）の買い注文をしても約5万株強に
制限されることを確認済み。関連する株式/市場/財務テスト10本、
既存の `venture-investment-outcome-test.js`（分割売却に書き換えて対応）、
全8シャードのcanonical suiteすべて成功（既知の無関係な構造的失敗2件を除く）。

**これにより、小型株モードの実装に着手できる状態になった。**

## 6. 実装方針（バグ修正後）

### 新規モジュール

`js/pe-mode-*` と同じ命名規則で独立モジュールとする案（例: `js/microcap-listings.js`）。
PEモードとは無関係な機能だが、検証手法（決定論ハッシュ、状態設計と計算を先に固める、
簡易シミュレーションでの事前較正）は踏襲する。

### 状態設計

```js
state.microcapMarket = {
  nextSpawnWeek: 0,        // 次回上場の週（8〜18週後の範囲で決定論的に抽選）
  listings: []             // 過去の上場履歴（上限を設けてslice）
}
```

`nextSpawnWeek` は上場が起きるたびに、`unit()` を使って
`現在週 + between(8, 18, 'microcap-spawn', 現在週)` の形で再抽選する
（範囲抽選方式。§3.1参照）。`g.market` へ直接 `push` する形は既存の
`listStartup()` と同じパターンを踏襲する。

### 決定論

PEモード同様、`Math.random()` を新規に呼ばない。既存の `hash()` / `unit()` /
`between()` 方式を使う。

### セーブ互換

トップレベル追加のため、旧セーブでは `microcapMarket` が存在しない状態で
問題なく読み込めるようにする（`mergeDefaults` で補完）。

## 9. 実装タスク（このまま実行してよい）

```

docs/MICROCAP_MODE_DESIGN.md の §1〜6 を前提とします。

js/engine.js の buyStock()/sellStock() の数量上限バグは

このリポジトリは決定論を設計原則としています。Math.random() を

- 既存の js/engine.js の g.market / buyStock() / sellStock() /

state.microcapMarket = {
  nextSpawnWeek: <次回上場の週>,

状態でも問題なく読み込めるようにしてください（mergeDefaults等で補完）。

### 3. 出現ロジック（範囲抽選）

週次処理で state.week が nextSpawnWeek に達したら新規上場を発生させ、
次回の nextSpawnWeek を「現在週 + 8〜18週後」の範囲で決定論的に
再抽選してください（between() を使用）。固定間隔にしないこと。

### 4. アーキタイプ抽選

上場のたびに決定論的ハッシュで、以下のアーキタイプから1つを選んでください。

- 駄目株（出現比率55%）: trend -0.003, vol 0.08, 上場時PER=0（無収益）
- 堅実（28%）: trend 0.0015, vol 0.08, 上場時PER 14程度（黒字）
- 隠れた優良株（12%）: trend 0.006, vol 0.13, 上場時PER 9程度（黒字）

「上場時に黒字かどうか」が唯一プレイヤーに見える手がかりです。
黒字グループ（堅実・隠れた優良株・本物の当たり）は上場時点では
互いに区別できません。

手がかりには15%のノイズを入れてください（駄目株が稀に黒字を装う、
本物の当たりが稀に無収益で上場する）。完全な攻略法にしないためです。

trend/volの具体的な適用方法は、既存の updateMarket()
（move = trend + (economy-1)*.018 + rand(-vol,vol)）と同じ式に
乗せる形で構いません。

### 5. 上場処理

- 評価額10〜19億円程度、発行株式数100万株（既存のlistStartup()に倣う）
- g.market へ直接push（既存のVC投資パイプラインは経由しない）

### 6. 売買

既存の buyStock()/sellStock() をそのまま使ってください。新しい
売買ロジックは不要です。保有期間の制限も設けないでください
（いつ売るかはプレイヤーの判断に委ねます）。

## 検証

以下を実測して報告してください。産物は「production の週次エンジンを

- セーブ互換: 旧セーブ（microcapMarketが存在しない状態）を読み込んで
  問題が起きないか

## 必ず守ること

- 既存のセーブデータの互換性を壊さない
- 既存のテストを壊さない。壊れる場合は個別に報告する
- 1PRで1機能。PEモード・起業パートリバランスとは別のPRにする
```
