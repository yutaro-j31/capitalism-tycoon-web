# 01 プロジェクト概要

## 1. プロジェクト名

- 日本語名: 資本主義ポケット TYCOON
- 英語名・リポジトリ名: Capitalism Tycoon Web
- リポジトリ: `yutaro-j31/capitalism-tycoon-web`
- 正式プラットフォーム: ブラウザ
- 最重要端末: iPhone

## 2. ビジョン

本作は、単一店舗の経営から始まり、複数店舗、本社組織、資金調達、株式上場、M&A、ベンチャー投資、不動産、持株会社経営へ発展する長期型の資本主義シミュレーションである。

プレイヤーは単に売上を最大化するのではなく、次の複数の責任を同時に管理する。

- 顧客価値
- 店舗収益性
- 従業員と組織
- 資金繰り
- 借入と株主資本
- 会社価値
- 個人資産
- リスク
- 長期的な企業存続

最終的な目標は固定された一つのエンディングではない。プレイヤーは自分の経営方針によって、優良企業、急成長企業、配当企業、投資会社、持株会社、世界企業など異なる成功像を構築する。

## 3. プロダクト方針

### 3.1 ブラウザ版を正本とする

すべての主要機能はブラウザ版で動作することを前提とする。ネイティブアプリ化を行う場合も、可能な限り同一ロジックと同一データモデルを再利用する。

### 3.2 iPhoneファースト

主要な設計判断は、iPhone縦画面で快適に遊べるかを基準にする。

- 主要操作は片手で届く領域へ置く。
- 重要な数値は横スクロールなしで読めるようにする。
- モーダルの多重表示を避ける。
- タップ対象は十分な大きさを確保する。
- 週送り前に重要な警告を確認できるようにする。
- 画面遷移回数を減らす。

### 3.3 長期プレイを中心に据える

短時間の達成感と長期的な複利成長を両立する。数十週で主要システムを理解でき、数百週から千週以上でも新しい目標が残る構造を目指す。

## 4. 想定プレイヤー

中心となる対象は次の層である。

- 経営シミュレーションが好きな人
- 株式、企業、財務に興味がある人
- スマートフォンで長期間遊べるゲームを求める人
- 自由度の高いプレイを好む人
- 数字を見ながら改善することを楽しむ人

専門的な会計知識を必須にはしない。ただし、表面的な数値ゲームではなく、プレイを通じて売上、利益、キャッシュフロー、負債、株式価値の違いを自然に理解できる設計とする。

## 5. プレイヤーの成長段階

### Stage 1: 創業

- 1店舗から開始
- 商品、価格、原価、広告、設備を調整
- 赤字回避と運転資金確保が中心

### Stage 2: 多店舗化

- 支店開設
- 店舗別損益管理
- 店長や従業員配置
- 標準化と地域戦略

### Stage 3: 企業化

- 本社部門の設置
- 人事、経理、商品開発、宣伝、技術、投資機能の整備
- 借入、増資、取締役会、役員報酬の管理

### Stage 4: 資本市場

- 外部投資家からの資金調達
- 企業価値評価
- IPO準備と上場
- 株価、配当、株主構成への対応

### Stage 5: 複合企業化

- M&A
- VC投資
- 不動産
- 新規事業
- 持株会社的な資本配分

### Stage 6: 永続経営

- 世代交代
- 役員退職と後継者育成
- 世界企業ランキング
- 実績、殿堂、長期目標
- 数百年規模の企業存続

## 6. 成功と失敗

### 6.1 成功

成功は単一のスコアで固定しない。以下の複数軸を持つ。

- 会社価値
- 売上規模
- 営業利益率
- 自己資本比率
- フリーキャッシュフロー
- 個人純資産
- 従業員満足度
- ブランド力
- 世界企業ランキング
- 永続年数
- 実績解除数

### 6.2 失敗

失敗には段階を持たせる。

- 一時的赤字
- 資金繰り悪化
- 債務超過
- 借入条件違反
- 支払不能
- 事業売却
- 経営権喪失
- 倒産

単純に現金が一度マイナスになった瞬間に終了させるのではなく、救済策、資産売却、借換え、増資、リストラクチャリング等を通じた再建余地を設ける。

## 7. 非目標

初期段階では次を主要目標にしない。

- リアルタイム対人戦
- 高精細3D表現
- 複雑なアクション操作
- 端末性能に依存する重い演出
- 会計監査レベルの完全な法定会計再現
- 現実企業名や実在人物の直接利用

ただし、ゲーム内部の会計ロジックは、プレイヤーが理解可能な範囲で一貫性を持たせる。

## 8. プロジェクトKPI

開発判断では、機能数だけでなく以下を追跡する。

- 進行不能率
- セーブ読込失敗率
- 週送り処理時間
- iPhoneでの主要操作完了時間
- 100週、500週、1200週回帰試験の成功率
- 倒産理由の分布
- 特定戦略への偏り
- 主要画面の誤タップ誘発箇所
- 重大な会計不整合件数

## 9. 品質の定義

本作における品質とは、機能が多いことではない。次の条件を継続的に満たすことを品質と定義する。

- プレイヤーの意思決定が結果へ合理的につながる。
- 数字の変化を説明できる。
- 同じ条件で結果を再現できる。
- 古いセーブから継続できる。
- 長期プレイで壊れない。
- iPhoneで迷わず操作できる。
- 新機能追加後も既存システムが破綻しない。
