# Offline K evidence archive builder

`node scripts/parallel-shard-k-archive-build.cjs SOURCE_ROOT PIN ROOT_A ARTIFACT_ID_A ROOT_B ARTIFACT_ID_B OUTPUT_GZ` packages two **already downloaded and extracted** K artifact roots. Both Node22/24 artifacts are required. Use the exact full source SHA and a tracked-clean source checkout. Relative roots are resolved before metadata enumeration; K test bodies are not executed. The caller must first verify GitHub run/job/artifact IDs, final HEAD, source pins, ZIP digests and CI/review status separately. The builder does not authenticate a supplied artifact ID or fetch GitHub.

The builder preserves every regular file's relative path, SHA256 and raw bytes as canonical base64 in the existing `k-full-artifact-evidence-v1` gzip format. It rejects links/nonregular entries, more than89 files per artifact, excessive file/total bytes and a JSON payload larger than the existing16MiB restoration bound. It does not select only passing files or silently drop unknown files. The existing restoration validator still requires exactly89 files per Node (full report, controls,3×29 per-PID logs), allowed paths, unique artifact IDs, matching Node versions, valid hashes/base64 and successful namespace controls.

Before writing, the builder calls the **unchanged strict K evidence auditor** against the explicit source metadata: all four passes,29 commands, byte output, memory, process cleanup and write observations must satisfy its existing checks. Missing/inconsistent/failed/incomplete evidence fails before output is published. A complete evidence pair with a raw cross-Node output difference is still retained, but returns **exit2 / cross-node-output-review-required**, not success. No bytes or output differences are normalized. Exit0 means this supplied pair passed that audit scope; it never authorizes production. Exit1 indicates invalid input, failed audit or a save error. Original extracted inputs are unchanged on every path.

`OUTPUT_GZ` must not already exist; saving uses exclusive creation and refuses to overwrite prior work. The JSON result records gzip SHA256, compressed size and the audit result. The same ordered input bytes and builder/compression runtime produce the same archive; cross-runtime gzip identity is not promised. Hash-pin saved archives independently when replaying them through `parallel-shard-k-evidence-audit.cjs --archive`.

Regression controls join the existing required K evidence self-test chain. They replay the independently hash-pinned historical fixture without new workload execution, prove stable bytes/strict restoration, retain its known cross-Node stderr gap, reject missing/extra/corrupt logs, links, duplicate IDs and wrong source, and verify refused overwrite/corrupted-output preservation. These are packaging controls, not fresh hosted performance/safety evidence.

This utility does not change a workflow, parallelism, runner, required gate or production economic code. J/C remain2; E/K remain1; E #1203 stays Owner-held. Runtime/host/API observation limits of the underlying auditor remain. Keep original artifacts for failure investigation if the strict pack builder rejects them; do not loosen the auditor to produce a successful archive.
