## 2. 合格基準（数字で判定する）

すべての画面が、390×664・創業直後の状態で次を満たすこと。`node scripts/ui3-screen-metrics.js --ui=3 --enforce` が0で終われば合格。

| 基準 | 値 | 理由 |
| --- | --- | --- |
| 画面の長さ | 2画面分以内 | 詳細はシートへ逃がす。長い一覧も初期表示は2画面分まで |
| 最小の文字 | 13px | これより小さい文字は置かない。例外なし |
| タップできる部品 | 44×44px以上 | 主ボタンは48px |
| 横方向のはみ出し | なし | |
| ページエラー | 0件 | |

計測できないが必ず守ること：

- **1画面の主ボタンは1つ。** 金色（`--u-accent`）のボタンは1画面に1つだけ。
- **数字と単位を改行で分けない。** 金額には必ず `.u-money`（`white-space:nowrap`）。
- **会社のお金は青、個人のお金は紫。** 例外なし。どちらの財布か分からない金額を出さない。
- **増減の色は緑と赤だけで伝えない。** 必ず `+` `−` の符号を付ける。
- **確認が要る操作はシートで確認する。** ブラウザの `confirm()` を新しく使わない。
- **ホバーに頼らない。** 長押しにも頼らない。

## 3. 画面構成

下のタブは5つに固定する。現在の19画面（`g.selectedTab` の値）は消さず、5つのタブの中に並べ直す。`g.selectedTab` の値と意味は変えない。

| タブ | 入る画面（`selectedTab`） | 上部チップの並び |
| --- | --- | --- |
| ホーム | `home` `missions` `news` | なし（`missions` と `news` はホームから開くシート） |
| マップ | `map` | 地図上の絞り込みチップ |
| 事業 | `business` `office` `strategy` `overseas` `media` `rivals` | 店舗・事業／本社／戦略／海外／メディア／競合 |
| 投資 | `market` `venture` `ma` `assets` `pe-portfolio` | 株式／ベンチャー／M&A／不動産／PE（解放後のみ） |
| 会社 | `bank` `report` `founder` `legacy` `settings` | 資金調達／決算／創業者／承継／設定 |

- タブを押すと、そのタブで最後に見ていた画面に戻る。初回は表の先頭。
- 画面の切り替えは、既存の `data-action="tab" data-tab="<id>"` をそのまま使う。

## 4. 部品

定義は `ui3.css`。新しい見た目が必要になったら、まずここにある部品で組めないか確かめる。組めないときは `ui3.css` とこの表に部品を足してから使う。画面ごとの独自の見た目を作らない。

| クラス | 使いどころ |
| --- | --- |
| `.u-card` | 数字のまとまり。1画面に2枚まで |
| `.u-stat`（`.hero` で大） | ラベル＋数字＋増減。横に並べるときは `.u-stats`（3列）か `.u-stats.two` |
| `.u-action`（`.warn` で注意） | 「今週やること」「次の一手」。カード全体が1つのボタン |
| `.u-list` と `.u-row` | 一覧。1行は左に名前と補足、右に数字と増減。行を押すと詳細シート |
| `.u-chips` と `.u-chip` | 画面の切り替え（`aria-current`）と絞り込み（`aria-pressed`）。横に流す |
| `.u-seg` | 2〜4択の切り替え（口座、業種など） |
| `.u-btn`（`.primary` `.wide`） | シート下端のボタン |
| `.u-badge`（`.good` `.warn`） | 状態を示す短い語 |
| `.u-pin`（`.tenant` `.store` `.realestate` `.rival`） | 地図の目印。見た目32px、当たり判定44px |

色と文字の値は `ui3.css` 冒頭の `--u-*` を使う。色コードや文字サイズを画面のCSSに直接書かない。

## 5. 画面ごとの仕様

### 5.1 ホーム（`home`）

上から順に、これだけを置く。これ以外は置かない。

1. 会社名と成長段階のバッジ
2. 数字のカード：**今週の利益**（大・前週比つき）、売上、企業価値、店舗数
3. **今週やること**：`.u-action` を最大3件。出どころは既存の Executive Secretary の優先順位と創業ガイドの現在の手順。危険（資金不足など）があれば `.warn` で先頭に出す
4. ニュース：最新2件。押すと全件のシート（`news`）

細部（2026-11-11 確定）：

- 成長段階のバッジは、`engine.growthMilestones()` のうち、並び順で最後に達成済みのものの名前。
- 「今週やること」の並びは、秘書の優先度が critical のもの（`.warn`）→ 創業ガイドの現在の手順 → 残りを秘書の優先順位の順。合わせて最大3件。
- ニュースの行は、UI3-9でシートに替わるまでは `news` 画面へ移動する（`data-action="tab"`）。
- 増減は `+` と `−`（U+2212）の符号を付け、金額は `compactYen` で整形する。
- 資金繰りが「安定」でない間、ホームは現行UIで出る（6.5）。危機対応の操作がそこにしか無いため。

現行ホームの「30秒で読む会社ホーム」などの読み物は置かない。必要な情報は「会社 › 決算」に移す。

### 5.2 マップ（`map`）

- **地図は現行の3D表示（`js/city-lab-map.js`）をそのまま主役にする。** 平面の地図に置き換えない。見本の地図は、実際のゲームの3D表示を写したもの。
- 地図は上のバーから下のタブまでの全面。現行（366×416）より広く取り、建物の高さと街並みが見えるようにする。
- ピンは建物の屋上の位置に立てる（現行の3D座標の投影をそのまま使う）。選択中の建物は、現行の選択枠を金色（`--u-accent`）にして強調する。
- ピンを選んでシートが出たら、その建物がシートに隠れない位置（地図の見えている部分の中央）に来るようカメラを寄せる。
- 地図の上に重ねるのは、絞り込みチップ1行と、右端の拡大・縮小・一覧の3ボタンだけ。現金や「今週の経営判断」の札は置かない（上のバーとホームにある）。
- 目印は種類ごとの丸いピン。**名前の札は選択中の1つにだけ出す。** ピン同士の衝突で隠さない（隠すのは画面外のときだけ）。
- ピンを押すと下からシートが出る（高さ58%まで）。地図は上に残す。
- 「一覧」ボタンで、同じ絞り込みの一覧シートを出す。
- 3D地図・Canvas2Dの予備表示・カメラの決まりは `CLAUDE.md` §4 のまま。変えるのは地図の上に載る部品とピンの見た目だけ。

### 5.3 出店シート（マップでテナントを選んだとき）

1. 見出し：テナント名、適性バッジ、補足1行（商圏・交通量・週額賃料）
2. 業種の切り替え `.u-seg`
3. 数字3つ：初期費用、週の利益見込み、回収までの週数
4. 補足1行：出店後の会社現金、開店までの週数
5. 下端：`試算の内訳`（内訳のシート）と **`出店する`**（主ボタン）

`出店する` は既存の最終確認（`confirmOpenStore`）につなぐ。既存の `open-store` は `#business-<テナントID>` の値を読むので、同じIDの入力を必ず用意する。

### 5.4 週間レポート

1画面のシートに収める。スクロールさせない。

1. 見出し：`第N週の結果` と、結果を一言で表す文（黒字／赤字／現金が減った、など）
2. 数字：**利益**（大）、売上、会社現金。それぞれ前週比つき
3. 今週の出来事：最大2件
4. 次の一手：`.u-action` 1件
5. 下端：`詳しい決算`（`report` へ）と **`閉じる`**（主ボタン）

現行レポートの「利益と現金の差」の内訳などは「会社 › 決算」に置く。

実装で決めたこと（UI3-2、2026-11-11。設計担当の確認待ち）：

- 週間レポートは画面ではなくシートとして登録する（`registerSheet('weekly-report', {render})`。6.1）。`?ui=3` のとき、`js/app.js` の `showWeeklySummary()` が先に `modules.ui3.renderSheet('weekly-report', …)` を呼び、答えがあればそれを `#modal-root` に入れる。週を進める2か所（1週間・4週間）のどちらも同じ関数を通る。
- 見出しは、上に `第N週の結果`、その下に一言文。一言文は、利益が黒字のとき「黒字が続いています」（前週も黒字）／「黒字でした」／現金が減ったとき「黒字でしたが、現金は減りました」、赤字のとき「赤字が続いています」（前週も赤字）／「赤字でした」／現金が減ったとき「赤字で、現金も減りました」、ゼロのとき「収支はゼロでした」／現金が減ったとき「利益は出ず、現金は減りました」。現金の増減は、現行のレポートの「利益と現金の差」と同じ `finance.cashBridge(g, 'week')` の「今週の現金増減」。
- 数字は、利益（大）・売上・会社現金。値と前週比は `ceoDashboard.weeklyImpact`。符号と色の規則はホームと同じ（5.1）。
- 今週の出来事は、その週のニュース（`g.news` のうち `第N週：` の N が `summary.week` と一致するもの）の先頭2件。文頭の `第N週：` は取る。`summary.newNews` は使わない（前回のレポート以降に増えたものなので、古い週を含みうる）。1件も無いときは「大きな出来事はありませんでした。」とだけ出す。（2026-11-11 設計担当が確定）
- 次の一手は、秘書の危険（critical）なタスク（`.warn`）→ 創業ガイドの現在の手順 → 秘書の先頭のタスク → 「ホームを見る」の順で1件。押すと、`secretary-jump` や `founding-tutorial-jump` ではなく **`tab`** でその画面へ移る（この2つはモーダルを閉じないため）。
- 下端は `詳しい決算`（`tab` → `report`）と `閉じる`（`close-modal`。主ボタン）。
- 1画面（スクロールなし）に収めるため、`css/ui3-weekly-report.css` で、シートの中の隙間・カードの内側の余白・出来事の行の最小の高さを詰め、出来事の見出しと次の一手の見出しを2行まで、補足を1行までにしている（色と文字の大きさは触っていない）。
- このシートは、現行UIが出している画面（まだ移していない画面）の上にも出る。現行UIの固定バーの重なり順は、v3のシートの初期値（50/51）より上なので、この週間レポートのシートだけ、現行のモーダルと同じ100/101にしている。また、現行UIのCSSが `#modal-root` の中の `h2` `p` `small` の色を強制するため、見出しは `h2` ではなく `role="heading"` の `div` にし、次の一手の補足の色だけ上書きしている。ほかのシートも現行UIの上に出るなら、`ui3.css` の `.u-scrim` `.u-sheet` の重なり順を直すほうが筋（設計担当の判断）。

### 5.5 そのほかの画面の型

残りの画面は、次の3つの型のどれかで作る。各画面で決めるのは表の4項目だけ。

- **一覧型**：絞り込みチップ → `.u-list`。行を押すと詳細シート
- **詳細シート**：数字3つ → 補足 → 下端に主ボタン1つ

| --- | --- | --- | --- | --- |

| `media` | 一覧 | — | 広告・広報の施策 | 実行する |
| `rivals` | 一覧 | — | 競合企業 | （読むだけ） |
| `market` | ハブ | 買える現金・保有の時価・含み損益 | 銘柄 | 買う・売る |
| `venture` | ハブ | 投資枠・投資先の数・評価額 | 投資先と候補 | 出資する |
| `ma` | 一覧 | — | 買収候補と進行中の案件 | 交渉を進める |
| `assets` | ハブ | 保有物件の数・時価・賃料収入 | 物件 | 買う・売る |

## 6. 実装の決まり

### 6.1 切り替え方（UI3-0で実装済み）

- v3は現行UIと並んで動く。`?ui=3` を付けて開くとv3が有効になり、その端末の `localStorage['capitalism_tycoon_ui']` に記憶される。`?ui=2` で解除。**この設定はセーブデータに入れない。**
- 画面は1つずつ移す。`modules.ui3.registerScreen(<selectedTabの値>, {render})` で登録した画面だけがv3で描かれる。**登録していない画面は、現行UI（D UI）が外枠ごとそのまま出る。** 創業画面とゲームオーバーは、それぞれの作業で移すまで現行UIのまま。
- 入口は `js/app.js` の `render()`。`modules.ui3.rendersNatively(tab, g)` が真なら `modules.ui3.renderApp(...)` の結果を `#app` に入れる。偽なら `leaveNative()` を呼んで従来どおり描く。
- v3の画面にはD UIの後処理をかけない。`js/ui-enhancer-registry.js` の `runUIEnhancers()` は、v3の画面が出ている間（`modules.ui3.isNativeActive()`）は何もしない。現行UIに戻ると再開する。
- v3が描く最上位の要素に `class="ui3"` が付く。`ui3.css` は `.ui3` の内側（と、v3の画面が出ている間だけ付く `body.ui3-native`）にしか効かない。
- 全画面への到達は `[data-action="tab"][data-tab="<id>"]` で保証する。v3の枠は、画面に出ていないチップの分も含めて、隠した一覧（`[data-ui3-all-screens]`）に全画面のボタンを持つ。

画面の登録のしかた（`js/ui3-<画面>.js`）：

```js
(function(){'use strict';
const modules=globalThis.__capitalismTycoonModules;
modules.ui3.registerScreen('home',{
  // 返すのは <main id="screen"> の中身だけ。上のバー・進めるボタン・タブは枠が描く。
  // 事業・投資・会社の各画面では、見出し（タブ名）とチップも枠が描くので、画面側では見出しを出さない。
  render({engine,g,engineModule,esc,money}){
    return `<h1 class="u-h1">${esc(g.companyName)}</h1>`;
  }
});
})();
```

- `render` は文字列を返すだけ。`g` を読むのはよいが、書き換えない。利用者由来の文字列は必ず `esc()` を通す。金額は `money()`（`compactYen`）で整形する。
- シートは `modules.ui3.sheet({eyebrow,title,subtitle,body,actions})` の結果を `#modal-root` に入れる。閉じるのは既存の `data-action="close-modal"`。シートが出ている間、進めるボタンは自動で隠れる。
- 画面ではなく、`js/app.js` が出す現行のモーダルを置き換えるシートは、`modules.ui3.registerSheet(id, {render})` で登録する（`id` は `modules.ui3.SHEET_IDS` のもの。今は `weekly-report` だけ）。`render(context)` は `{eyebrow,title,subtitle,body,actions}` を返し、枠が `sheet()` で包む。`context` は `{engine,engineModule,g,esc,money}` と、呼び出し側が渡す値（週間レポートでは `summary`）。`js/app.js` は `modules.ui3.renderSheet(id, context)` を先に呼び、答えが空文字（`?ui=3` でない、未登録、未設定のゲーム）のときだけ、現行のモーダルを出す。
- スクリプトは `index.html` で `js/ui3-shell.js` の後、`js/app.js` の前に読み込む。

**現行UIの機能は、`js/app.js` が描くHTMLだけではない。** 約80個の enhancer が、描画後に画面へ機能を差し込んでいる（不動産の管理、危機対応、資本配分のメモなど）。v3の画面ではこれらが動かないので、画面を移すときは、その画面に差し込まれている機能も対応表（5.5）に載せ、v3側で出し直す。

### 6.2 ファイル

| 置き場所 | 中身 |
| --- | --- |
| `css/ui3.css` | `docs/ui-v3/ui3.css` と同じ内容。片方だけ変えない（一致を検査で守る） |
| `css/ui3-<画面>.css` | その画面だけの配置。色・文字サイズは書かない |
| `js/ui3-shell.js` | 上のバー・タブ・進めるボタン・シートの開閉 |
| `js/ui3-<画面>.js` | 1画面1ファイル。`registerScreen` を呼ぶだけ。`js/` の直下に置く（下位フォルダは既存の検査が認めない） |

新しいJSを足したら、同じPRで `index.html` と `tests/fixtures/module-load-order.json` を更新する。新しいCSSは `index.html` の `css/ui3.css` の後に足す。

新しい `js/ui3-*.js` が `companyCash` や `personalCash` などのお金の項目を読むと、経済エンジンの「書き込み箇所の一覧」の検査（`AUTHORITATIVE_WRITER_INVENTORY`）が、語が出てくるだけで候補として検出する。同じPRで `node scripts/phase0-5-acceptance.js --refresh-writers` を実行し、`docs/economic-engine/phase0-5-authoritative-writers.json` の差分が**自分のファイルの追加だけ**であることを確かめてコミットする。`exactAuthority` 側（実際の書き込み）に差分が出たら、それは状態を書き換えているということなので、コードを直す。

枠の検査（`tests/ui3-shell-webkit-test.js`）は、画面のスクリプト（`js/ui3-shell.js` 以外の `js/ui3-*.js`）を読み込まない状態でページを開き、検査用の仮の画面だけを登録して確かめる。**画面を移しても、この検査は変えなくてよい。** 画面ごとの検査は `tests/ui3-<画面>-webkit-test.js` に書き、そちらは実際のスクリプトを読み込んだ状態で確かめる。

検査の置き場所：v3の検査は `tests/ui3-*-webkit-test.js` とし、`tests/test-execution-registry.json` に登録して、`.github/workflows/test.yml` の「iPhone Acceptance Playthrough」ジョブに手順を足す。`tests/run-all.js` には足さない（登録数がシャードの保存済み証跡で固定されているため）。手元では `UI3_TEST_BROWSER=chromium UI3_TEST_CHROME=<Chromeのパス>` で実行できる。

### 6.3 してはいけないこと

- **エンジンの状態を直接書き換えない。** 操作は必ず既存の `data-action`（`js/app.js` の `action()`）を通す。新しい操作が要るなら、エンジン側の既存の関数を呼ぶ `action` を足す。
- 描画の中で乱数を使わない。`Math.random()` を使わない。
- 起動時の MutationObserver と、外部 enhancer の登録を増やさない（上限79）。
- `css/app.css` を変えない（バイト一致の検査がある）。
- 既存のテストを消さない・外さない・緩めない。現行UIのテストは、切り替えが終わるまで現行UIに対して通り続けること。

### 6.4 文言

- 画面の文言は日本語。英語の見出し（CEO DASHBOARD など）を置かない。
- 金額は既存の `compactYen` などの整形関数を使う。独自に整形しない。
- 1つの `.u-row` の補足は1行まで。説明文を置きたくなったら、その画面に置く情報が多すぎる。

### 6.5 現行UIに任せる状態（届き先が決まっていない操作の既定の扱い）

現行の画面には、特定の状態のときだけ出る操作がある（例：資金繰り危機のときの回復策）。その操作のv3での届き先がこの文書に無いときは、**止まらずに、その状態の間だけその画面を現行UIで出す。** 操作は1つも失われず、v3側の作り込みは後の作業に回せる。

- 画面の登録に `useCurrentUI(g)` を足す。真を返す間、その画面は現行UIが外枠ごと出る。偽に戻ればv3に戻る。

  ```js
  modules.ui3.registerScreen('bank',{
    useCurrentUI:g=>Boolean(g.someState),   // 読むだけ。g を書き換えない
    render(context){ /* ... */ }
  });
  ```

- 条件は、できるだけ狭く書く（「その操作が出る状態」だけ）。常に真を返す登録はしない。
- 使ったら、必ず `migration-ledger.md` のその画面の表に、状態・現行UIで出る操作・残件を書く。
- 残った分は UI3-9b でv3に作り直す。**UI3-11（切り替え）の時点で、`useCurrentUI` と枠の規則は1つも残っていないこと。**

枠が最初から持っている規則（`js/ui3-shell.js` の `CURRENT_UI_RULES`）：

- **ホーム × 資金繰りが「安定」以外**：現行ホームに差し込まれる危機対応のパネル（`js/player-crisis-ui.js`）が、回復策の唯一の入口のため。この間、v3のほかの画面には枠が「資金繰り危機」などの札を出し、押すとホーム（現行UI）へ移る。

### 各作業の進め方

**着手したら最初にやること**

1. 対象の画面を仮に登録した状態で、既存の `tests/ui3-*-webkit-test.js` を実行し、落ちるものが無いか確かめる。落ちたら、実装に入る前に報告する。
2. 現行の画面を実際に開き、出ている操作（`data-action`）を洗い出して、`migration-ledger.md` にその画面の表を作る。創業直後だけでなく、台帳の「確かめる状態」に挙げた状態でも洗い出す。enhancer が差し込む操作も含める。
3. 表のすべての行に、v3での届き先を書く。届き先が決まらない行は、6.5の扱い（その状態の間だけ現行UI）にして、残件として書く。

**PRに必ず入れること**

1. `node scripts/ui3-screen-metrics.js --ui=3 --enforce --screens=<対象>` の出力。
2. 390×664の画面写真（初期表示と、主な操作のシート）。
3. `migration-ledger.md` のその画面の表（届かなくなる操作が0であること）。
4. `?ui=3` なしで現行UIが変わっていないことを、既存の検査で示した結果。
5. この文書に書かれていない判断をしたら、同じPRでこの文書に書き足し、PR本文の「自分で決めたこと」に並べる。
6. 決められなかった点があれば、PR本文の「未決事項」に、選択肢と推奨を添えて書く。

### 担当が自分で決めてよいこと・止まること

**決めてよい（この文書に書き足して先へ進む）**

- エンジンや既存の画面にすでにある概念・値・文言から選ぶだけの判断（例：バッジにどの既存の値を使うか）
- 並び順、文言の言い回し、既存の部品の組み合わせ方
- 届き先が決まらない操作を、6.5の扱いにすること
- `js/ui3-shell.js` への小さな追加。条件は、既存の動きを変えない追加であること、`tests/ui3-shell-webkit-test.js` に確認を足すこと、PR本文の「枠の変更」に書くこと。枠の既存の動きを変える必要があるときは、止まる

**止まる（設計担当に戻す）**

- 新しいゲームの概念や数値を作る必要がある
- `ui3.css` に無い新しい部品、または新しい操作（`action`）が要る
- お金や状態を書き換える処理に触れる必要がある
- 既存のテストを変えないと通せない
- 6章の決まりを守ったままでは実装できない
- UI3-9b と UI3-11

止まるときも、手を止めるのは**その点だけ**。それ以外を実装し、未決事項つきの下書きPRを出してから報告する。設計担当の答えは、同じPRへの追加コミットで取り込む。

### どのモデルに任せられるか

設計上の判断はこの文書で済ませてあるので、UI3-1以降は軽いモデルで進められる。上位モデルが要るのは次の場面だけ（依頼文と戻し方は9章）。

- **UI3-0**：現行の描画・後処理との切り分けを決める作業。
- **UI3-11**：既存テストの置き換え計画。
- **UI3-9b**：仕様を書く作業（実装は軽いモデルで可）。
- 各PRの内容確認と、上の「止まる」に当たる判断。
