# セキュリティ・データ保護・チート耐性仕様

## 1. 目的

本章は、ブラウザ版ゲームの保存データ、外部連携、公開環境、開発権限を安全に扱うための最低基準を定義する。

## 2. 基本原則

- クライアント入力を無条件に信用しない
- 秘密情報をリポジトリ、フロントエンド、ログへ含めない
- 権限は最小限にする
- セーブ互換性と復旧可能性を優先する
- チート対策で通常プレイを破壊しない

## 3. 秘密情報

APIキー、トークン、秘密鍵、接続文字列は環境変数またはGitHub Secretsで管理する。

禁止事項:

- ソースコードへの直書き
- PR本文やIssueへの貼付
- クライアント配信物への埋込み
- ログへの出力

漏えい疑いがある場合は直ちに失効・再発行する。

## 4. 依存関係とサプライチェーン

- lockfileを保持する
- 不要な依存関係を追加しない
- 依存更新はCIと回帰試験を通す
- 既知脆弱性を定期確認する
- install scriptや外部コード生成物を無検証で実行しない

## 5. Webセキュリティ

以下を基本防御とする。

- XSS対策として動的文字列を適切にエスケープ
- HTML文字列の直接挿入を避ける
- 外部URL、ファイル入力、インポートデータを検証
- CSP導入を検討
- HTTPSのみを使用
- 外部リンクには必要に応じてnoopener/noreferrer

## 6. セーブデータ保護

セーブはローカル保存であっても不正・破損入力を想定する。

読込時に以下を検証する。

- JSON構文
- saveVersion
- 必須フィールド
- 数値範囲
- 安定ID参照
- 株式数、残高、借方・貸方の不変条件
- NaN、Infinity、負数禁止項目

検証失敗時はゲーム状態へ部分適用しない。

## 7. インポート・エクスポート

- ファイルサイズ上限を設ける
- MIME種別と内容を検証する
- 予期しないプロパティは無視または拒否する
- インポート前に現在セーブをバックアップする
- エラー位置を利用者へ分かる形で示す

## 8. チート耐性

本作は原則としてシングルプレイであり、完全な改変防止は目的としない。

ただし以下は検知または隔離可能にする。

- 不正な資金増加
- 発行済株式数と持分合計の不一致
- 会社資産から個人資産への無根拠移動
- 週番号や履歴の逆行
- 未解放機能の不正状態
- 乱数状態の欠落・不整合

改変セーブは「検証されていないセーブ」として識別できる設計を推奨する。

## 9. 決定論と改ざん検知

必要に応じて以下の要約値を保存する。

- 重要状態のハッシュ
- 直近週の入力要約
- seed / RNG state
- appVersion
- saveVersion

これは競技的な不正防止ではなく、バグ診断と再現性確保を目的とする。

## 10. GitHub権限

- mainへの直接pushを避ける
- 必須CIとPRレビューを設定する
- Actions権限を最小化する
- 外部PRでSecretsを利用するworkflowを慎重に扱う
- Dependabot等の自動PRも通常の検証を省略しない

## 11. プライバシー

テレメトリを導入する場合は、収集目的、項目、保存期間、第三者提供の有無を明示する。氏名、メール、端末固有識別子、セーブ全文は原則収集しない。

## 12. セキュリティ事故対応

1. 漏えい範囲の特定
2. 秘密情報の失効
3. 影響機能の停止または隔離
4. 修正と回帰試験
5. 影響説明
6. 再発防止策のdocs反映

## 13. リリースゲート

P0/P1の未解決セキュリティ問題、公開Secrets、任意スクリプト実行、セーブ破壊リスクがある場合はリリースしない。
