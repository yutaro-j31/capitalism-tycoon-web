# 用語集・未決定事項・仕様変更履歴

## 1. 目的

本章は、仕様書間で用語の意味を統一し、未決定事項と仕様変更を追跡可能にするための正本である。

## 2. 主要用語

### ゲーム進行

- 週送り: プレイヤーの確定操作後に1週間分のシミュレーションを進める処理
- gameWeek: ゲーム開始からの通算週番号
- 四半期締め: 13週単位で実行する集計・評価処理
- 年度締め: 52週単位で実行する決算・評価処理
- 決定論: 同じ初期状態、入力、seedで同じ結果になる性質

### 経営・会計

- 会社資産: 法人に帰属する現金、店舗、株式、不動産等
- 個人資産: プレイヤー個人に帰属する現金、株式、不動産等
- 仕訳: 取引を借方・貸方で記録したもの
- 営業キャッシュフロー: 本業から生じた現金増減
- ランウェイ: 現在資金で事業を継続可能な推定期間
- 財務制限条項: 借入契約上の財務条件

### 株式・資本政策

- Pre-money: 資金調達前の企業価値
- Post-money: 資金調達後の企業価値
- 希薄化: 新株発行等で既存株主の持分比率が低下すること
- 非支配持分: 連結子会社のうち親会社以外が保有する持分
- のれん: 買収価格と識別可能純資産との差額
- Exit: IPO、M&A、株式売却等による投資回収

### 店舗・市場

- キャパシティ: 店舗が一定期間に処理可能な最大需要
- 失注: 需要はあったが能力、在庫、待ち時間等で販売できなかった件数
- 共食い: 新店舗・新商品が既存店舗・商品の需要を奪うこと
- 市場飽和: 供給能力が地域需要に対して過剰な状態
- 市場集中度: 売上や供給が少数企業へ集中する程度

### 開発・試験

- 安定ID: 保存後やバージョン更新後も同一対象を識別するID
- SAVE_KEY: ブラウザ保存領域で使用するセーブ識別子
- saveVersion: セーブ構造のバージョン番号
- 不変条件: 実行中常に成立すべき整合性条件
- seed: 疑似乱数列を再現するための初期値
- 自動プレイ: Playwright等で戦略に基づきゲームを連続操作する試験

## 3. 用語運用ルール

- 同じ概念に複数名称を使わない
- UI表示名と内部識別子を混同しない
- 新規用語は本章へ追加する
- 略語は初出時に正式名称を併記する
- 金額、比率、週数の単位を明記する

## 4. 未決定事項の管理

未決定事項は以下の形式で記録する。

- ID
- 論点
- 選択肢
- 判断基準
- 影響範囲
- 暫定方針
- 決定期限または判断条件
- 状態: OPEN / DECIDED / DEFERRED / REJECTED

## 5. 現在の主要未決定事項

### OQ-001 オンライン保存

- 論点: ローカル保存のみか、アカウント同期を導入するか
- 暫定方針: ローカル保存を優先
- 判断条件: 認証、運用費、プライバシー、競合プレイ需要

### OQ-002 課金方式

- 論点: 買い切り、無料体験付き買い切り、追加コンテンツ
- 暫定方針: ゲーム設計を課金に依存させない

### OQ-003 ゲーム終了条件

- 論点: 完全ゲームオーバー、再起、世代交代後継続
- 暫定方針: 倒産理由を明示し、再挑戦導線を持たせる

### OQ-004 難易度

- 論点: 固定難易度か動的難易度か
- 暫定方針: プレイヤーに隠れた救済補正を避け、開始条件と市場条件で調整

### OQ-005 外部テレメトリ

- 論点: 匿名分析を導入するか
- 暫定方針: 明確な必要性と同意設計が整うまで導入しない

## 6. 仕様変更履歴ルール

仕様変更時は以下を記録する。

- 日付
- 変更ID
- 対象文書
- 変更内容
- 変更理由
- セーブ互換性への影響
- 決定論への影響
- 会計への影響
- 必要なテスト
- 関連Issue / PR

## 7. 変更区分

- PATCH: 誤記、説明補足、実装影響なし
- MINOR: 後方互換性を維持する仕様追加
- MAJOR: セーブ構造、主要ループ、会計、データモデルに影響する変更

MAJOR変更は移行計画と回帰試験を必須とする。

## 8. 初期変更履歴

- SPEC-002: ブラウザ版・iPhone最優先を明文化

## 9. 完了条件

未決定事項を実装者の推測で確定してはならない。実装に影響する判断はdocsと関連Issue/PRへ記録する。
