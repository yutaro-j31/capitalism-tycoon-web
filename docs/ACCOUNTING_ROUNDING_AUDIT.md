# 週次現金丸め補正の監査方針

週次処理では、会社現金が丸め前の集計値で更新される一方、会計仕訳は各取引を小数2桁へ丸めて保存するため、処理件数が多いシナリオでは毎週数厘から数銭の差が線形に累積することがあります。

今回、差が5銭以内の場合に限り、週次財務スナップショットの `endingCash` を正規の丸め済み会社現金として採用します。5銭を超える差は記帳漏れの可能性があるため補正せず、従来どおり会計検証で失敗させます。

補正は原因を隠さないよう、`g.finance` に次を保存します。

- `roundingAdjustmentTotal`: 符号付き累積補正額
- `roundingAdjustmentAbsoluteTotal`: 相殺前の絶対累積補正額
- `roundingAdjustmentCount`: 補正回数
- `roundingAdjustmentHistory`: 直近52件の週・補正額・補正前差額

`finance.validate()` は、会計開始から52週ごとに1円の監査許容量を設定し、絶対累積補正額がこれを超えた場合にエラーとします。208週では4円が上限です。観測された正常な丸め差は週約0.006円で、208週でも約1.25円に収まるため、この閾値は通常の浮動小数点・個別仕訳丸めを許容しつつ、毎週数銭規模の実際の記帳漏れを検知する余裕を持たせています。

PR #301で店舗週次収支を仕訳単位の整数円へ統一し、supply-longの全条件で補正回数0・累積0円を確認しました。現時点で供給系・在庫簿価・AP/AR/working capitalに具体的な不一致は観測されていないため、これらは将来の整数円マイグレーション候補として別Issueで管理し、失敗seed・取引・差額が観測された時点で着手します。

根本的に全週次計算を仕訳単位の丸め値へ統一するとゲームバランス、既存セーブ、長期決定論へ広範な影響が及ぶため、未観測領域への一括適用は行いません。累積監査が閾値を超えた場合は補正上限を広げず、発生源を新規会計バグとして調査します。
