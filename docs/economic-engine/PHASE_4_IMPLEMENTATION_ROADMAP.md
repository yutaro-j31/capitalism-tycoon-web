## 1. Implementation order and approval boundary

Lowest-risk future first code PR: **P4-1 pure schema/validator**, then P4-2 raw-state read adapter. No save fields, no startup normalization, no principal/rate/cash writers, no simulation draws. Pure offline fixtures can be designed before Phase3 exit, but even these implementation PRs are not authorized by the current Owner request (current scope is docs only).

P4-0 is this preparation package. P4-1–P4-8 are non-authoritative pure/isolated preparation; P4-9 is a separate authority adoption proposal. P4-10 is not a single broad migration: each approved borrower/product cohort becomes its own PR and cannot overlap another active authority PR. P4-11 integration and P4-12 exit require an explicit declared scope; canonical support for absent LBO/fund/SPV products is **schema capability only**, not runtime financing.

Every PR starts from refreshed origin/main, checks active work and authority manifest, records base/final-head SHAs, audits installed wrappers and tests, inspects final diff, executes relevant gates and waits for applicable head CI. Do not push a new commit over in-progress same-head CI except explicit superseding instruction. Reuse successful same-head evidence; only rerun unchanged failures with documented infrastructure reason. Do not consume Codex automated review quota solely to obtain a ritual review; perform explicit diff/source/contract audit, disclose if same-agent rather than independent review. Owner merge permission is separate; **this docs PR waits for Owner approval**.

## 2. Common slice contract (applies to every row)

These requirements are part of each slice, not optional boilerplate:

1. Purpose, file/API/state scope, legacy writer relationship and dependencies are in §3.
2. Monetary effects use [Design §4](PHASE_4_DEBT_INSTRUMENT_DESIGN.md); pure/metadata slices have **zero** cash/ledger mutation. Principal never expenses; accrued and paid interest separate.
3. Live changes use existing `engine.runTransaction` and storage checkpoint, no dedicated debt restore/save framework. All same-intent economic legs + contract state + receipt + counters commit once. Rejected save/post-save failure restores live/mirror/cache/pending/durable behavior under shared contract. Predecessor pending write survives. No premature notify/emit.
4. No Math.random/Date.now/name entropy; preserve existing persisted simulationRng.seed/state/draws on pure reads and failed operations. New debt IDs derive from borrower + instrument + accepted intent/sequence in same transaction; stable codepoint sort/tie-break, not localeCompare or object insertion order.
5. Each implementation concern gets failing contract/reproduction first (RED), then GREEN on final implementation. No fabricated RED by changing valid baseline fixture, no weakened invariants. A pure feature absent on baseline can have missing API/validation as RED; legacy fault RED uses installed writer.
6. Node tests must enter canonical tests/run-all.js and A–L shard contract. WebKit real browser/real IDB required for live writer, adoption, UI or save-order changes; pure slices may reuse boot gate and existing main WebKit without falsely claiming browser debt scenario coverage. Test wiring/workflow changes, if needed beyond minimal test registration, get their own CI concern PR.
7. Complete only with scoped contracts, actual evidence, parity/replay and applicable final-head CI PASS (skipped must be genuinely non-applicable), no new unresolved P0/P1 introduced, final diff audit, recorded authority status and migration risks. Owner decides product policy and source-of-truth adoption; no undocumented blanket permission inferred from a prior slice.

## 5. Test case specification

| Case | Oracle / negative conditions |
|---|---|
| Origination | borrower cash +P, correct lender cash −P/receivable+P, face+P, zero P&L, fees separate; credit unavailable, duplicate ID, wrong borrower account reject unchanged |
| Accrual vs payment | accrual increases expense/payable without cash; payment cash−I/payable−I with no expense; due subset no extra liability; principal unchanged |
| Scheduled/early/maturity | face decreases exactly paid principal, no P&L; payment bounds, partial due, residual cent, remainingWeeks0 with unpaid face; negative cash never clamped up; contract prepay rights |
| Refinance | old face/payable close only if fully funded; new debt links predecessor; fees once; atomic insufficient funding or duplicate child rejects all |
| Reset/shock | observed percent/decimal normalized, caps/floors/lag and fixed protection; +100/+200/+500bps scenarios; reset twice same period no duplicate accrual |
| Covenant/default/workout | matched scope/window, ≤/> boundary, grace/cure, status does not extinguish debt; default owed principal counts; undefined tax/penalty/nonaccrual unavailable |
| Company sale/M&A | borrower ID and obligations survive share sale; refinance vs asset sale proceeds waterfall; guarantees separate; target debt never magically parent debt; fund cash untouched |
| Shared faults | `tests/helpers/transaction-fault-case.js` all available kinds: save-false, mirror, enqueue-false/throw, save-throw, saved/change/notify throws; optional save-before-throw; finance/reducer throws; nested calls; pending valid predecessor; live/storage/cache unchanged on reject; flush, production reload, fresh durable-only hydration; monotonic saveSequence |
| Replay/retention | same intent/event receipt exactly once before/after compaction and reload; same amount legitimate different intents; failed retry allowed; closed receipt watermark; active/ready contracts not deleted by caps |
| Determinism | persist requested simulationRng.seed, record roots/version/state/draws; nuisance names don't change rates/IDs; serial vs reload+compacted fork same semantic hash; sort ties stable; differing seed must change relevant stochastic path before statistics |
| Performance/storage | tick/close/serialization/load/durable-write p50/p95/p99/max, raw/stored bytes, peakRSS/memory proxy, operation/receipt growth, monetary envelope, save-time and iPhone foreground/background resume; compare accepted baselines, no invented universal budget |

Integration scenarios must include founder receivable, defaulted bank+gym, finance/property aliases, both company and personal mortgage forms, margin PIK/shortfall, old aggregate debt, inactive bond records and unsupported fund/SPV exposures. Ambiguity fixtures should fail certification rather than be rewritten to pass.

## 6. Long-run report contract

Record source/main/head SHA, harness/schema/formula/authority versions, supported entity/instrument counts, requested seed→persisted root provenance, scenario feature capabilities, time/rate environment, policies/commands, debt event counts, cash/principal/accrued-interest first-diff, invariant failures, final semantic hash and draw count, migration cohort and unknown liabilities, save raw/stored size and runtime metrics. Nightly reports may include expected economic default; default itself is not test failure. Unexplained money creation, missing obligation, nondeterministic result or save rollback leak is test failure.

Adoption coverage and budgets must be reviewed before calling the first code slice complete. Forecasted or synthetic performance remains labelled estimate/synthetic; no physical-device claims from WebKit emulation.
