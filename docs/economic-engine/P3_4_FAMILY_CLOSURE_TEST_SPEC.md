## 1. Reading rules

`FC-Gnn-kk` is a stable proposed case identifier: inventory GAP number and case number within it. There are **64 case groups**: six for G01, five for G08, five for G13, and one for each of the other 48 GAPs. A group can be parameterized over entry/account/fault/seed; 64 is not a count of executed tuples. Priority P0 means the three requested prerequisite families, P1 means identity/persistence/individual command prerequisites, P2 means owning-slice acceptance or specification follow-up. These are scheduling priorities, not incident severities. Sizes S/M/L estimate one future concern PR; a case group does not authorize bundling different writer migrations.

S obligations: **F** family/caller closure, **A** owner/issuer/class attribution, **M** conservation and monetary rounding, **S** rejected-save/throw rollback, **L** durable reload/compaction, **R** replay, **D** determinism, **W** real WebKit, **P** permanent registration. Each §3 row inherits the explicit fixture/fault/oracle/execution definitions here; its row-specific recipe and delta are mandatory, not replaced by generic helper success.

The approved [#1080 §3.1–§3.3/§5](PHASE_3_P3_4_PREFLIGHT_AND_DESIGN.md) gateway uses existing quantity fields; activation waits for every player-common fact writer, not every unrelated issuer's adoption. Excluded adjacent issuers must remain isolated. Generation 2+ is currently refused; a new issuer authority or durable identity schema is not proposed here. Follow [#1082 NG-01–NG-16](PHASE_3_P3_4_NEW_GAME_GENERATION_REFOUNDING_SPEC.md) without duplicating that contract. #1086 merged at `bd780b2f`; `js/phase3-ownership-planner.js:8`–`:25` declares fact-leg policies, not callable routing, apply, money freshness or an installed authority. ### 1.1 Shared fixtures and exact oracles

**N0 (new game):** `tests/harness.js` loadGame with a deterministic LCG; call installed `engine.createInitialState({configured:true})`, construct TycoonEngine, then configure the supported founding route as the reused fixture does. Start each parameter independently. Use store/digital/investment when the case crosses refounding. Establish valid finance opening books, save successfully, flush, and capture a baseline with nonzero founder/treasury/personal buckets where relevant. Scenario-only setup of a fresh state is allowed in future tests; label direct field preparation synthetic, not a reachable gameplay proof. For financial cases establish holdings/paid claims through installed commands, or explicitly disclose a minimal synthetic setup and add a successful installed command proving the target precondition. Never import an arbitrary historical save as the required start.

**TX:** a failure matrix at the actual installed transaction boundary: save false; save throws before admission; denied localStorage mirror; enqueue false/throw; accepted save then throw; saved/change callback throw; finance/event/finalization throw where actually used. Notify throw is included only where that notifier is inside the failing boundary. Add direct and outer runTransaction entry, predecessor pending-save variants, normal success and recovery retry. Every applicable injection must increment a hit counter after the target mutation has been observed. Pre-admission save throw necessarily precedes persistence admission, not necessarily the ownership write. If a callback cannot fire, show the call-path evidence and label that tuple N/A, never silently skip. The Node helper's soft-failure mapping is not a universal return type for every command: pin the installed adapter's documented false/error/object contract and reject success-shaped results on aborted commits.

**O0 (rejection):** same live root and exact complete live state including ledger, all quantity buckets, history, RNG state and event bookkeeping; mirror and sync cache bytes equal pre-attempt bytes; durable bytes equal the captured durable predecessor before flush, then equal the captured accepted pending predecessor after it drains. No failed candidate put survives, no successful receipt/toast, no ownership token authorizes the failed result. Compare host RNG draw counts. Record saveSequence separately: preserve prior bytes on failure and require monotonic recovery/retry sequences; do not demand equality of successful save metadata across time. For normalized reload use the same explicitly enumerated metadata exclusions as the existing economic oracle, not a blanket strip of news/finance/ownership/RNG. SH event differences need G38 review, not silent relaxation.

**O1 (success/replay):** exact intended quantity/owner delta, conservation, one committed receipt and no cross-account leakage, reload and fresh durable-only hydration, recovery-save flush, then retry/terminal replay according to operation identity. Repeating a valid independent buy/split is a new operation, not an idempotent retry. Weekly/terminal actions with the same source ID/week are inert only where their installed contract says so. Twin fresh games with the same seed and action/fault schedule must yield identical economic state, ledger and simulationRng; unrelated weekly RNG consumption is permitted but must match twins and roll back on failure. Pure readers/planners consume no RNG or clock.

**M0 (deferred money oracle):** no fractional concrete amount is fixed in this specification. After the named owning slice is DONE, that slice's acceptance PR chooses raw operands and an independently calculated expected whole-yen result under contract §3–§4; check exact state/ledger payer/payee totals and allocateYen sum, not merely call the implementation helper on both sides. Respect caps and derived residuals. Share counts/ratios are not rounded with ceilYen. Before R9, a fresh test can encounter unmigrated fractions; isolate migrated writers with whole opening balances. Whole-game strictness starts in a game created after R9. Preserve pre-R9 stored values under contract §1.1; no load re-rounding. M0 is not a ninth-slice omnibus follow-up.
