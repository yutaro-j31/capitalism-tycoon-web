## Boundary and evidence legend

- DIRECT: method mutates then calls save/emit; no enclosing runTransaction in that method. Inspect installed caller; a weekly/delegated caller can supply an outer transaction, a direct UI call cannot assume one.
- TX: installed public engine API uses runTransaction, checkpoint/deferred save and rollback; raw exported helpers are not independently atomic.
- WEEK: installed canonical advanceWeek boundary in play-runtime-compat/engine owns state+finance+RNG+ID counters and one save. Calling raw module service alone does not provide that boundary.
- NESTED: store-open or other caller must supply the transaction; helper itself has no save.
- SHADOW: M&A financing executes on clone, validates, copies to live, saves with checkpoint rollback. Not generic Core debt settlement.
- LOAD: normalization/migration, not an economic operation; must never be called by the new read-only adapter.
- MIXED: direct action/sale uses DIRECT, service uses WEEK; exact methods noted below.

All persisted fields listed here use the existing v9 root save through engine/save-storage. Cache admission, localStorage mirror and queued durable IDB are separate checkpoints. No row claims durable success from a return value alone. Tests named below are existing coverage references, not an assertion that every fault/hydration branch is covered or was run here. All monetary signs describe borrower effects.
