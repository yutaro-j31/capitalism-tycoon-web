## 1. Boundary, ledger and evidence profiles

Use profiles with the rows below to specify every writer's transaction/save/ledger semantics:

| Profile | Transaction and persistence | Accounting |
|---|---|---|
| D | Direct live mutation + `save()`/emit; rejection ignored. No universal command wrapper. | Company action may call finance.event; personal action generally has no standalone finance ledger. |
| T | Installed Engine action calls runTransaction; one shared checkpoint/commit-time save. Code evidence, not blanket fault verification. | Explicit company event(s); personal branches generally do not have full entity ledger. |
| C | Custom clone → validate → replace live → save/emit with shared storage checkpoint; not an outer live runTransaction. | Explicit finance events in shadow; caller must prove nested/post-save behavior. |
| W | Installed weekly caller enclosed by canonical whole-week runTransaction and close. Direct module calls alone do not get that protection. | Company finance events or subsystem summary; see row. |
| H | Helper is not safe as a public writer by itself; caller owns boundary. | Caller/helper explicit events. |
| N | normalize/ensure/load compatibility mutation; outer command/week boundary cannot be assumed. | May rebase opening finance state; not ordinary economic settlement. |
| O | Observer/derived/mirror only. Writes diagnostic/cache state, not authorized origination. | No second posting or cash mutation. |
| X | Deliberately inactive economic entry point. | No new cash or principal change permitted. |

`B` = company finance `debtBorrowing` cashEffect +P, liabilityEffect +P, profitEffect 0. `P` = `debtRepayment` cashEffect −P, liabilityEffect −P, profitEffect 0. `I` = `interestExpense` cashEffect −I, profitEffect −I, principal unchanged. `F` = fee explicit cash/P&L effect as implemented. `none(person)` means no company ledger, **not** proof of a complete personal ledger. All existing-test names below are under `tests/` and end in `-test.js` unless explicitly noted. Listed tests are existing coverage, not a claim every fault is tested or that every listed test was rerun here. See audit executed-test table.

## 5. Projection identity, duplication and reconciliation rules

1. Use existing company/founder IDs from economicReadModel; reuse existing loanID when unambiguous. Do not mint persisted IDs during read. Entity-qualified namespace distinguishes same loanID across borrowers; raw original ID retained in sourceRef. Duplicate source IDs are an error, not automatically suffixed by array index.
2. `bankFinancing.loans[].financeLoanID/id` aliases one finance loan; do not sum bankDebt plus companyDebt. Market `propertySecuredLoan` finance row aliases `realEstateMarket.loans[].id`; rows must reconcile by ID, principal, status, owner and property. One is the contractual servicer; one finance mirror. Generic finance repayment is a competing mutator that needs synchronization before cutover.
3. Company total must separately report finance principal, observed companyDebt, unmatched legacy realEstate loans, independent properties mortgage exposure and unsupported bond records. Do not add all blindly. `match=ambiguous` stops certification.
4. PersonalDebt includes general/market/legacy collateral debt and shortfalls. Itemized market/legacy balances are components when evidenced; personal-holding mortgages and margin balance are additional liabilities. Compute aggregate residual only when component inclusion and nonnegative residual are proven. A residual is `legacy-aggregate-unknown`, not a fabricated bank contract. Tax-origin residual is not assumed interest-bearing borrowing.
5. Defaulted balance still owed; closed/paid with positive balance is inconsistent. Exposure uses amount and legal obligation evidence, not only active status. No due date inferred from mutable remainingWeeks without issue/payment/moratorium history.
6. Total group legal debt counts each borrower once; guaranteed exposure separately caps guarantee; never multiply a subsidiary's legal debt by ownership percentage. Economic look-through share is a separate labelled scenario. No parent cash settles fund/sub debt solely because voting control is high.
7. Adapters return `{sourceRef, aliasRefs, confidence, unknownFields, anomalies, authority:'legacy-read-only'}`. Unknown lender maps to approved `external:lender` only as aggregate unknown counterparty, not a specific bank. No mutating ensure/quote/default migration API calls.
