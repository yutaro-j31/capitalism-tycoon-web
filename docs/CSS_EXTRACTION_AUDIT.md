# CSS Extraction Audit

Date: 2026-07-14

## Scope

This audit records the Phase 0 CSS extraction from `index.html` to `css/app.css`. It separates facts directly observed in the repository from implementation inferences.

## Facts confirmed in code before extraction

- `index.html` had 1 static `<style>` element.
- The static `<style>` element started in the `<head>` on line 2, immediately after the `<title>` element and before `</head>`.
- Because there was only one static `<style>` element, the stylesheet order was the exact order inside that block.
- The block contained CSS custom properties in `:root`: `--bg`, `--bg2`, `--panel`, `--panel2`, `--line`, `--text`, `--muted`, `--gold`, `--green`, `--red`, `--blue`, `--radius`, and `--shadow`.
- The block contained 5 media queries: 1 `@media(max-width:1050px)` block and 4 `@media(max-width:720px)` blocks.
- The block did not contain `@supports`, `@keyframes`, or `@-webkit-keyframes` rules.
- The block included pseudo-class and pseudo-element selectors including `:root`, `.tabs::-webkit-scrollbar`, `.btn:hover`, `.btn:active`, `.btn:disabled`, `:last-child`, `:focus`, `:nth-child(...)`, and `:first-child`.
- The block included mobile layout rules in the `@media(max-width:720px)` sections.
- The block used `env(safe-area-inset-bottom)`, `env(safe-area-inset-left)`, and `env(safe-area-inset-right)`.
- The block used `position: fixed` for the bottom tabs, modal backdrop, toast, and game-over overlay, and `position: sticky` for the top bar and market header.
- Bottom navigation CSS was present under `.tabs`, `.tabs::-webkit-scrollbar`, `.tabs button`, `.tabs button.active`, and related mobile rules.
- Modal CSS was present under `.modal-backdrop`, `.modal`, `.modal-actions`, `.summary-modal`, and `.summary-head`.
- Graph, card, and table-related CSS was present under `canvas`, `.card`, `.card-head`, `.card-body`, `.market-table`, `.market-row`, `.forecast`, and `.history-table`.
- The result sharing image is generated by JavaScript canvas drawing in `downloadResultCard()` rather than by a separate static CSS block.
- The static CSS did not contain `url(...)` image or font references.
- `index.html` contained inline `style` attributes generated by JavaScript template strings, including progress bar widths and customer segment bar widths. These were not part of the extracted static stylesheet.
- JavaScript references class names through generated HTML strings and dynamic state, including `active`, `show`, `success`, `error`, `warning`, `good`, `warn`, `done`, `up`, `down`, and many structural classes used by rendered templates.
- JavaScript checks `modal-backdrop` through `classList.contains('modal-backdrop')`.
- JavaScript reads `--gold` via `getComputedStyle(document.documentElement).getPropertyValue('--gold')` for canvas line drawing.
- No service worker file, manifest file, or explicit cache asset list was found in the repository with the inspected paths/patterns.

## Facts after extraction

- Static CSS now lives in `css/app.css`.
- `index.html` loads the stylesheet with `<link rel="stylesheet" href="./css/app.css">`.
- The link uses a relative path so GitHub Pages subpath deployment under `/capitalism-tycoon-web/` can resolve it from `index.html`.
- No static `<style>` element remains in `index.html`.
- No service worker or manifest change was required because none was present.

## CSS left in `index.html`

No static `<style>` block was intentionally left in `index.html`.

The remaining CSS-like content is runtime-generated presentation data inside JavaScript strings or canvas drawing code, for example dynamic `style="width:..."` values and colors passed to the canvas context. These were left in place because moving them would change JavaScript behavior or generated image behavior and was outside this Phase 0 CSS-only extraction.

## Inferences and review notes

- The single original `<style>` element means preserving rule order only required copying that element's content into `css/app.css` without reordering.
- The `./css/app.css` relative path is appropriate for GitHub Pages project sites because it is resolved relative to the current document URL rather than from the domain root.
- Since there is no service worker or manifest in the current repository, adding a new service worker or cache manifest would introduce behavior outside the requested scope.
- Dynamic classes in JavaScript should continue to work because class names and CSS selectors were not renamed or consolidated.
