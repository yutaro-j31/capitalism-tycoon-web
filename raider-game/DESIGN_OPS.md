# 子会社の事業経営 設計書（第1版・2026-11-24）

壁打ちで決まったこと：
- 経営モードは会社ごとに選ぶ。一度変えたら4週間は変えられない。
- 方針経営のCEO提案は四半期ごと。内容は設備投資・値付け・新商品（タイプ別の操作）・人員。
- 商品ラインの数は可変。そのほかの細かさは本書の案のまま。
- 航空・海運の路線を地図に出す。
- 不動産はデベロッパーとして、用地取得・設計・販売・運用まで行える。ごくまれに地面師詐欺。物件詳細に建物の絵を出す。
- ライバルも同じ操作を使って競う。
- 既存の子会社は、今の売上・利益に合うように自動で移行する。
- 上手に経営すれば、今より大きく儲かる。
- 週間業績は本社単体だけにする。

---

## 0. 原則
- **土台は今の市場**：地域×業種ごとの需要 `M.D`、シェア、業界の設備過剰 `M.glut`、好不況の波 `icState` を使う。数式を一から作り直さない。
- **全社が同じ仕組みで動く**：プレイヤーの会社（直接経営か方針経営）も、ライバルの会社も、どこにも支配されていない会社も、同じ関数で売上と費用を計算する。違うのは誰が決めるかだけ（プレイヤー・子会社CEO・AI）。
- **決定論**：判断と出来事は、シミュレーションの乱数（`rnd`）か状態のハッシュで決める。画面の表示は乱数を使わず、状態も変えない。
- **重さの上限**：毎週の計算は全社で今の2倍以内にする（約150社。iPhoneで1週の処理が50ms以内）。AIの判断は四半期ごとに行う。
- **会計の一貫性**：会社の売上・費用は `c.rev`・`opProfit(c)`・`c.ni` に集約する。連結・税・評価など今の仕組みは、そのまま使えるようにする。

## 1. 共通の土台

### 1.1 データ（会社ごと `c.ops`）
```
c.ops = {
  type: 'prod' | 'cmdty' | 'sub' | 'bank' | 'pipe' | 'dev',  // 業種からタイプを決める（表1）
  mode: 'direct' | 'policy',     // プレイヤーの会社だけが使う（ほかの会社はAIが決める）
  modeW: 週,                     // 最後にモードを変えた週（ここから4週は変えられない）
  pol: {goal: 'grow'|'profit'|'share'|'fix', capex: 上限, hire: 上限},  // 方針経営の方針
  wk: [{w, rev, cogs, sga, op}],  // 直近13週の実績（会社画面用）
  ...タイプ別の項目（2〜6章）
}
```

| 表1 業種とタイプ | タイプ |
|---|---|
| 小売・食品・自動車・テック | ① 商品型 `prod` |
| 鉄鋼・海運・エネルギー・航空 | ② 市況・設備型 `cmdty`（海運・航空は路線を持つ） |
| 通信 | ③ 契約型 `sub` |
| 銀行 | ③ 銀行型 `bank` |
| 製薬 | ④ 開発型 `pipe` |
| 不動産 | ⑤ デベロッパー型 `dev` |

### 1.2 毎週の流れ
1. 市場の需要 `M.D` と市況を進める（今の `mkStep`）。
2. 各社のタイプ別の関数 `opsWeek(c)` が、操作の値から販売量・価格・原価・販管費を出す。
   - 売上 `c.rev`（年換算）＝ 週の売上 × 52
   - 営業利益 `opProfit(c)` ＝ 週の（売上 − 原価 − 販管費 − 固定費）× 52
3. 今の `coStep`（利息・純利益・配当・株価）がそのまま続く。

`c.margin` と `c.base` は、上の結果から毎週計算し直す（今の数式を参照している箇所はそのまま動く）。

### 1.3 経営モード（プレイヤーの子会社）
- **直接経営**：タイプ別の操作をプレイヤーがいつでも変えられる。
- **方針経営**：方針（成長・利益・シェア・再建）と、設備投資・採用の上限を決める。四半期ごとに子会社のCEOが提案を出す（受信箱の `opsprop`）。
  - 提案は操作の組み合わせ（例：「新商品を投入（費用8億円）」「料金を5%下げる」「高炉を1基休止」）。金額と、見込みの効果（CEOの能力に応じた誤差つき）を添える。
  - あなたは承認・一部修正・却下を選ぶ。2週間答えなければ「却下」とする。
  - 却下が3回続くと、CEOの士気が下がる（退職のリスクが上がる）。承認した提案が当たると士気と評価が上がる。
  - 提案の中身は、AIと同じ判断関数（7章）にCEOの能力と性格を加えて作る。能力が高いほど、見込みが正確で判断もうまい。
- 切り替えは会社画面のボタンで行う。変えた週から4週間はボタンを無効にし、理由と再開日を表示する。
- 今ある自動経営（委任 `c.dm`/`c.deleg`）は方針経営に移す（`deleg` の 成長／バランス／利益 を goal に写す）。

### 1.4 人と組織（全タイプ共通）
- 今の `c.wage`・`c.train`・`c.sat` を使う。
  - 賃金を上げる → 士気・品質・生産性が上がり、固定費も上がる。
  - 士気が低いと品質と稼働率が下がり、まれにストライキ（1〜3週の減産）。
- 人員は固定費として扱い、タイプ別の生産能力の上限に掛け合わせる。

### 1.5 週間業績と会社画面
- **週間業績**：本社単体の数字だけにする（本体の収支・配当・運用成績・本体のCF）。グループと会社別の推計は外す。
- **会社画面に「事業」タブを追加**：週ごとの実績（売上・粗利・営業利益）、タイプ別の指標、操作パネル（直接経営）または方針と提案の履歴（方針経営）。
- **グループタブ**：子会社の週次実績を一覧にする（実際の週次の積み上げ）。

## 2. ① 商品型（小売・食品・自動車・テック）

### 2.1 データ
```
c.ops.lines = [{id, seg, name, p: 価格倍率(0.6〜1.6), q: 品質(0〜100), cu: 単位原価, ad: 広告(週・億円), age: 週, ramp: 立ち上がり(0〜1), on: true}]
M.segs = {seg: 需要の比率}   // 市場の需要を分ける区分（業種ごとに3〜5、表2）
```

| 表2 業種と区分の例 | 区分 |
|---|---|
| 自動車 | 軽・セダン・SUV・EV・商用 |
| 小売 | 食料品・衣料・日用品・家電 |
| 食品 | 加工食品・飲料・菓子・冷凍 |
| テック | 端末・ソフト・クラウド・半導体 |

1社が持てる商品ラインは1〜6本。同じ区分に2本は持てない。

### 2.2 数式（週）
- 区分の需要：`Dseg = M.D × segs[seg]`。区分ごとの比率は、ゆっくり変わる流行で動かす（ハッシュで決める）。
- 魅力：`a = (q/50)^εq × p^(−εp) × brand^0.5 × (1 + 0.6 × adEff) × ramp × 陳腐化`
  - `εp`（値段への敏感さ）：小売2.0、食品1.6、自動車1.2、テック1.0
  - `εq`（品質への敏感さ）：小売0.6、食品0.8、自動車1.2、テック1.5
  - `adEff = 1 − exp(−ad / (0.002 × Dseg))`（効きは次第に鈍る）
  - 陳腐化：自動車は5年で−30%、テックは2年で−40%、小売・食品はほぼなし
- 区分内のシェア：`s = a / Σa`。今の `SHARE_SPEED` で目標値にゆっくり近づける。
- 販売量 `v = Dseg × s`（区分の需要は基準価格での金額）
- 売上 `= v × p × 市況の価格水準`
- 原価 `cu = 基準原価(業種) × (0.55 + 0.45 × q/50)^1.3 × 規模の利益(v^−0.08) × 賃金 × 原材料(rawF)`
- 品質の動き：研究開発費 `rd` で上がる（収穫逓減）。毎週0.2%ずつ下がる。
- 新商品：費用は区分の需要の5〜15%、立ち上がりに8〜26週（`ramp` が0→1）。同じ会社の近い区分から客を5〜10%奪う。
- 撤退：在庫処分として、その週の売上の20%を損失に計上する。

### 2.3 操作（直接経営）
商品ラインごとの価格・品質の投資・広告、新商品の投入、撤退。小売だけは「店舗数」を販売能力の上限として持つ（店舗の拡大は2.4で、地図の店舗表示は後回し）。

### 2.4 能力の上限
`v ≤ 生産能力`。能力は設備投資（今の `invest`）で増える。小売は店舗数が能力で、1店舗あたりの能力は業種の定数で決める。

## 3. ② 市況・設備型（鉄鋼・海運・エネルギー・航空）

### 3.1 データ
```
c.ops.cap = 生産能力（年・億円相当の数量）, util = 稼働率の目標, idle = 休止中の能力,
         build = [{amt, done: 完成週}], ctr = 長期契約の比率(0〜0.8), ctrP = 契約価格,
         hedge = [{kind: 'sell'|'fuel', amt: 比率, px: 固定価格, until: 週}]
S.cmdty[ind] = {px: 市況価格の指数, fwd: 先物の上乗せ}
```

### 3.2 数式（週）
- 市況価格：`px = 1 × (1 + 好不況の波(icState) × 業種の振れ幅) × (1 − 2 × M.glut) + 乱数の揺れ`
  - 振れ幅：海運0.6、鉄鋼0.4、エネルギー0.5、航空0.2
- 販売量：`v = min(cap × util, 業界の需要 × 能力シェア)`
- 売上 `= v × (ctr × ctrP + (1 − ctr) × px)`。売り側のヘッジがあれば、その比率の分は固定価格に置き換える。
- 変動費 `= v × 単位変動費 × 燃料・原料の指数`。費用側のヘッジがあれば固定する。
- 固定費 `= (cap − idle × 0.7) × 単位固定費`（休止中の能力は固定費の30%だけかかる）
- 市況が変動費を下回れば減産したほうが得になる（AIはそう判断する）。
- 増設：完成まで鉄鋼104週・海運78週・エネルギー156週・航空52週。費用は能力1あたりの業種定数で、建設中は利息も負担する。
- エネルギー：保有する資源量が毎年5%ずつ減る。探鉱に投資すると補充できる（成功確率つき）。

### 3.3 路線（航空・海運）と地図
```
c.ops.routes = [{id, a: 都市, b: 都市, n: 便数または船数, fare: 運賃倍率(航空のみ)}]
```
- **航空**：都市の組み合わせごとに需要があり、都市の規模の積を距離で割って決める。各路線で同じ路線を飛ぶ会社と客を取り合う（2章の魅力の式を運賃と便数で使う）。座席利用率＝需要の取り分÷座席数。
- **海運**：航路（例：アジア―欧州・アジア―北米・大西洋・中東―アジア）ごとに荷動きがあり、船の配分と長期用船の比率を決める。
- **地図**：都市を結ぶ曲線を描く。
  - 自社の路線は自社の色で太く、ライバルの路線は細く薄く描く。表示の切り替えができる。
  - 線をタップすると、その路線の数字を出す。
  - 線は今の地図のキャンバスに描き、DOMの要素は増やさない。

## 4. ③ 契約型・銀行型

### 4.1 通信（`sub`）
```
c.ops = {...共通, subs: 加入者(百万), arpu: 月額(千円), net: 回線品質(0〜100), cac: 獲得費の配分(週・億円), capex: 通信網への投資(週・億円)}
```
- 解約率（月）：`churn = 1.2% + 2% × max(0, arpu/平均 − 1) + 1.5% × max(0, (平均品質 − net)/50)`
- 新規加入：`gross = cac / 1人あたり獲得費 × (魅力シェア)`
- 回線品質：`capex` が維持に必要な額（加入者に比例）を下回ると毎週下がる。上回ると上がる（上限あり）。
- 売上 `= subs × arpu × 12`

### 4.2 銀行（`bank`）
```
c.ops = {...共通, dep: 預金, loan: 貸出, rL: 貸出金利の上乗せ, rD: 預金金利の上乗せ, std: 審査の厳しさ(0〜1), npl: 不良債権, reserve: 引当金}
```
- 預金は、自社の預金金利と市場平均の差に反応して、ゆっくり出入りする。
- 貸出の需要：`景気 × (1 − 0.6 × std) × 金利への反応` で決まる。上限は自己資本比率8%（貸出 ≤ 自己資本 ÷ 0.08）。
- 貸し倒れ（年率）：`PD = 基準1% × (1 + 1.5 × (1 − std)) × (1 + 2 × 信用環境(S.econ.credit)の4〜8四半期遅れ)`。引当金で吸収し、超えた分を損失にする。
- 純利益の元：利ざや（貸出 × (政策金利 + rL) − 預金 × (政策金利 + rD)）＋ 手数料 − 貸し倒れ。
- 自己資本比率が8%を下回ると、貸出が止まり、増資か資産売却を迫られる（受信箱）。

## 5. ④ 開発型（製薬）
```
c.ops.pipe = [{id, name, stage: 0〜4, area: 領域, cost: 週の費用, left: 残り週, pS: その段階の成功確率, peak: 承認後の年間ピーク売上, part: 提携の比率}]
c.ops.drugs = [{name, peak, age, lossW: 特許切れの週}]
```

| 段階 | 期間 | 週の費用（ピーク売上比） | 成功確率 |
|---|---|---|---|
| 基礎研究 | 52週 | 0.1% | 40% |
| 第1相 | 52週 | 0.2% | 60% |
| 第2相 | 104週 | 0.4% | 35% |
| 第3相 | 156週 | 0.8% | 60% |
| 承認申請 | 52週 | 0.1% | 90% |

- 各段階の終わりに、シミュレーションの乱数で成否を決める。失敗すれば計画は消える。
- 承認後の売上は5年かけてピークへ近づき、承認から10年で特許が切れて60%下がる。
- 操作：
  - 続ける・打ち切る（費用が止まる）。
  - **ライセンスアウト**：期待価値の50〜70%で権利を売る。
  - **ライセンスイン**：他社の計画を期待価値の110%で買う。
  - **提携**：費用と売上を相手と折半する。
- 期待価値は、残りの成功確率 × ピーク売上 × 利益率を割り引いて出す。調査部の能力で表示の誤差が縮む（いまの推定理論株価と同じ考え方）。

## 6. ⑤ デベロッパー型（不動産）

### 6.1 流れ
**用地取得 → 設計 → 着工 → 竣工 → 販売または保有して運用**

### 6.2 データ
```
S.sites = [{id, city, area: m², zone: 'com'|'res'|'ind', far: 容積率, px: 価格, risk: {soil, title}, own: 持ち主, w}]  // 都市の一覧から、ハッシュで作る（乱数を使わない・今の genProps と同じ方式）
c.ops.projs = [{id, site, kind: PROPの種類 + 'condo'(分譲マンション), grade: 'std'|'hi', gfa: 延床面積, cost, start, done, pre: 事前販売の比率, sold, how: 'sell'|'hold'}]
```

### 6.3 設計と費用
- 建てられる種類は用途地域で決まる。
  - 商業地：オフィス・商業施設・分譲マンション
  - 住宅地：賃貸住宅・分譲マンション・一棟アパート
  - 工業地：物流倉庫
- 延床面積は、敷地面積 × 容積率の50〜100%で選ぶ。
- 建築費 ＝ 延床面積 × 単価（種類・グレード・物価で決まる）。工期は規模に応じて52〜156週。
- **分譲マンション**：着工時から事前販売する（景気と価格で売れ行きが変わる）。売れ残りは竣工後に値引き販売する。
- **賃貸として保有**：竣工すると、今の不動産（`S.props`）に会社の物件として加わる。今の家賃・稼働率・評価の仕組みをそのまま使う。
- **竣工時に売却**：投資家へ、利回り（今の `PROP.y` と金利）で評価した価格で売る。

### 6.4 地面師詐欺（ごくまれ）
- 用地取得のたびに判定する。所有者の確認が弱い用地（`risk.title` が高い・相場より15%以上安い）は0.3%、それ以外は0.02%。
- 発覚すると、支払った代金を失う（回収は0〜20%）。ニュースになり、会社の評判が下がる。
- 防ぐ手段：取得前の権利調査（費用 = 価格の0.5%・2週）で確率を1/10にする。法務部の力でさらに下げる。

### 6.5 建物の絵（物件詳細）
- 建物の種類×グレードごとに、オリジナルの等角図（SVG）を画面内に描く。階数・色は規模とグレードで変える。
- 3Dのモデルは単一HTML・iPhoneでは重いので使わない。
- 地図上の小さな記号も同じ形を縮小して使う。

### 6.6 本社の投資部でもできるか
後述の確認事項1。

## 7. AI（ライバル・どこにも支配されていない会社・方針経営のCEO）
- **四半期ごとの判断**：タイプ別の操作の候補（値上げ・値下げ・新商品・増設・休止・ヘッジ・料金変更・審査の厳しさ・開発の打ち切りなど）を、次の4四半期の利益を簡単に試算して評価する。いちばん良いものを最大2つ選ぶ。
- **性格**：会社ごとに、攻撃的・保守的・価格重視・品質重視の傾向を持たせる。ライバルの社長の性格と、CEOの性格（今の `TRAITS`）から決める。
  - 攻撃的な会社は値下げと増設をしやすく、値下げ合戦の引き金になる。
  - 保守的な会社はヘッジと休止をしやすい。
- **判断の精度**：CEOの能力が高いほど試算の誤差が小さい。誤差はハッシュで決める。
- **競争の反応**：シェアを大きく奪われた会社は、次の四半期に対抗策（値下げ・広告・品質）をとりやすい。今の `competitorsReact` をこの形に置き換える。

## 8. バランスの目標
- AIの平均的な経営で、業種平均の利益率が今と同じになるよう定数を合わせる（移行の前後で、市場全体の売上・利益の差を5%以内に）。
- 上手な直接経営なら、業種平均の1.5〜2倍の利益率を数年続けられる。悪い経営なら赤字になる。
- 抜け道を防ぐ：
  - 価格倍率の上下限（0.6〜1.6）を設ける。
  - 広告と研究開発の効きは次第に鈍くする。
  - 能力の上限を超えては売れない。
  - ヘッジは最大80%・最長4四半期まで。
- 確かめる方法：今の戦略別ベンチマーク（20年×18通り）に、事業を直接経営するボット（素朴なルール）を足す。「AIの平均 < ボット < 上限」になっていることを確認する。

## 9. 移行（既存のセーブ）
- 読み込み時に、`c.ops` のない会社へ、今の数字に合うように作る。
  - **①商品型**：今の売上を、2〜3本の商品ラインに業種の区分の比率で分ける。品質は50、価格倍率は今の価格戦略（低・標準・高 → 0.9・1.0・1.1）に合わせる。単位原価は、今の営業利益になるように逆算する。
  - **②**：能力 = 販売量 ÷ 稼働率0.85。長期契約の比率は0.4、ヘッジはなしで始める。
  - **③**：加入者・月額料金、または預金・貸出を、今の売上と業種の定数から逆算する。
  - **④**：今の売上に合う承認済みの薬を2〜3本と、各段階の開発中の計画を置く。
  - **⑤**：今の売上を、保有物件の賃料と分譲の売上に分ける。
- 確認：移行した週と翌週で、各社の売上・営業利益の差が1%以内であること。
- プレイヤーの子会社は方針経営で始める。今の委任の設定（`dm`/`deleg`）を方針に写す。
- 保存形式はフィールドを足すだけにし、セーブキーは変えない。

## 10. テストの計画
- **移行**：全業種の会社で、移行の前後で売上・利益の差が1%以内。古いセーブがそのまま読める。
- **タイプ別の性質**（数式の向きを確かめる）：
  - 値上げするとシェアは下がり、単価は上がる。
  - 品質に投資すると、遅れてシェアが上がる。
  - 減産・休止すると、市況が安いときの損失が小さくなる。
  - ヘッジの損益が、市況と固定価格の差と一致する。
  - 解約率が料金と回線品質に反応する。
  - 銀行の貸し倒れが、信用環境に遅れて出る。
  - 開発の成功率が、多数回の試行で表の値に近い。
  - デベロッパーの事前販売・竣工・保有・売却で、現金と資産が一致する。
- **地面師**：発生率（1万回試行）と、権利調査による低下を確かめる。
- **経営モード**：切り替え後4週は変えられない。方針経営の提案（承認・修正・却下・期限切れ）が反映される。
- **AI**：値下げ合戦が起き、そのあと収まる。どこかの会社が際限なく儲け続けることがない（30年のシミュレーションで利益率の分布を確かめる）。
- **重さ**：iPhone相当の環境で1週の処理が50ms以内。
- **決定論**：同じシードで同じ結果。画面の表示で乱数の状態が変わらない。
- **地図と画面**：路線が描かれ、タップで数字が出る。320〜430px幅ではみ出さない。建物の絵が種類・グレードごとに出る。
- **既存の回帰**：全テスト、上場企業ごとの条件チェック、画面の無作為操作、長期シミュレーション。
